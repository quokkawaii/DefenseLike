# DefenseLike UX Design

## When to Use
- 화면 흐름, HUD, 유닛 배치, 함정/패링 입력, 상점·강화·컬렉션 UX를 설계할 때 사용한다.
- 시각·상호작용 요구사항이 비어 있거나 구현 전에 상태별 피드백이 필요할 때 사용한다.

## Required Inputs
- `확정` 또는 `승인` 상태의 요구사항과 수용 기준
- `docs/design-req.md`, `docs/game-req.md`, 현재 UI 구조 또는 에셋 제약

## Workflow
1. 플레이어 목표별 화면과 진입/이탈 경로를 정리한다.
2. 정상, 빈 상태, 잠김, 오류, 패배/승리 상태를 정의한다.
3. 키보드와 포인터 입력, 특히 패링 활성 시 스페이스바 우선순위를 명시한다.
4. 전투 가독성을 위해 타이머, 몬스터 누적 위험, 재화, 함정 상태 피드백을 정의한다.
5. 구현 가능한 컴포넌트와 관찰 가능한 수용 기준으로 넘긴다.
6. 화면·상호작용 결정마다 근거 요구사항 ID를 기록한다.

## Outputs
- 기본 핸드오프: `_workspace/02_ux_interaction-spec.md`
- 화면 흐름, 상태표, 입력표, 피드백, 접근성, 수용 기준을 포함한다.

## Validation
- UX 결정이 게임 규칙을 암묵적으로 변경하지 않는지 확인한다.
- 동시에 여러 함정이 활성화될 때 하나의 패링 객체가 공유된다는 요구사항을 보존한다.
- 미정인 시각 스타일을 확정하지 않는다.
- `제안`·`미정` 요구사항을 시각 디자인 제작 근거로 사용하지 않는다.
