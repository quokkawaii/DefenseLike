# DefenseLike Game Planning

## When to Use
- 전투 규칙, 성장, 경제, 난이도, 콘텐츠 범위 또는 수용 기준을 정리할 때 사용한다.
- 요구사항 충돌이나 미정 사항이 구현을 막는지 판별할 때 사용한다.
- 코드 구현이나 시각 디자인 제작에는 사용하지 않는다.

## Required Inputs
- 최신 `AGENTS.md`, 사용자 요청
- `docs/game-req.md` 및 관련 디자인/시스템 요구사항

## Workflow
1. 관련 문장을 출처와 함께 모으고 `확정`, `제안`, `미정`, `승인`으로 분류한다.
2. 플레이어 흐름, 상태 변화, 자원 변화, 예외 및 실패 조건을 명시한다.
3. 수치를 임의로 확정하지 않고 조정 가능한 파라미터와 목표 범위를 구분한다.
4. 범위를 현재 구현과 추후 개선으로 나눈다.
5. 각 항목에 고유 ID, 근거, Given/When/Then 또는 동등하게 관찰 가능한 검증 방법을 작성한다.
6. 충돌이 크면 대안을 제시하되 선택하지 않고 오케스트레이터에 올린다.

## Outputs
- 정본 핸드오프: 범위에 맞는 `docs/game-req.md`, `docs/system-req.md`, `docs/design-req.md`, `docs/product-req.md`
- 세션 간 중간 인계가 꼭 필요할 때만 `_workspace/01_requirements-draft.md`를 사용한다.
- 요구사항 문서가 기획 문서를 겸하므로 같은 내용을 별도 기획서로 변환하지 않는다.

## Validation
- 문서에 없는 결정을 확정 사실로 표현하지 않는다.
- `확정`·`승인`과 `제안`·`미정`을 분리하며 후자를 후속 제작 근거로 넘기지 않는다.
- 모든 수용 기준이 플레이 또는 테스트로 관찰 가능해야 한다.
- 아웃게임 영구 데이터와 한 판 종료 시 초기화되는 인게임 데이터를 혼동하지 않는다.
