# DefenseLike Implementation

## When to Use
- 승인된 게임/기술/UX 명세에 따라 코드, 데이터 또는 테스트를 변경할 때 사용한다.
- 요구사항 자체를 새로 결정해야 하는 작업에는 먼저 기획 또는 설계를 사용한다.

## Required Inputs
- 구현 가능한 `확정` 또는 `승인` 요구사항과 수용 기준
- 기술 설계, 소유 파일/디렉터리, 검증 명령

## Workflow
1. 최신 지침, 작업 트리, 관련 구현과 테스트를 확인한다.
2. 요청에 필요한 최소 변경을 하고 사용자 변경을 보존한다.
3. 인게임 상태와 영구 저장 상태의 경계를 코드와 테스트에 반영한다.
4. 소유하지 않은 파일이 필요하면 임의 수정하지 않고 오케스트레이터에 재배정 요청한다.
5. 가장 좁은 테스트부터 실행하고 결과와 미검증 범위를 기록한다.
6. 변경 및 테스트마다 근거 요구사항 ID를 기록한다.

## Outputs
- 요청된 코드/데이터/테스트 변경
- 필요 시 `_workspace/03_implementation_result.md`에 변경 파일, 결정, 검증, 잔여 위험을 기록한다.

## Validation
- 관련 수용 기준마다 코드 또는 테스트 근거가 있어야 한다.
- 빌드 산출물이나 공유 상태를 쓰는 테스트는 다른 작업과 직렬 실행한다.
- 기술 스택이 미정이면 임의로 프로젝트를 부트스트랩하지 않는다.
- `제안`·`미정` 항목은 구현하지 않는다.
