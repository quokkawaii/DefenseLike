# 기획 인터뷰 결정 이력 (보관)

이 파일은 `interview-state.md`에서 재개 속도를 위해 분리한 과거 결정 이력이다. 정본은 각 요구사항 문서(`docs/requirement/*-req.md`)이며, 이 파일은 이력 참조용이다.

## 직전 관련 결정

`UX-108`

- 최초 출시에는 크레딧 화면, 메뉴 항목과 엔딩 크레딧을 제공하지 않는다.
- 외부 자산·오픈소스의 라이선스상 의무 고지는 크레딧과 구분해 별도로 관리한다.

`GAME-170`

- 스크롤 선택 후 유효 지점은 밝게 표시한다.
- 무효 지점은 어둡게 표시한다.
- 유효 지점 클릭 시 별도 확인 없이 사용 요청한다.
- 우클릭 또는 `Esc`로 취소한다.

`GAME-171`~`GAME-173`

- `GAME-171`: 유효성 최종 검사 후 효과를 먼저 적용하고, 정상 적용된 경우 재화를 차감한 다음 구매 횟수를 증가시킨다.
- `GAME-172`: 사용 실패 시 효과·재화·구매 횟수를 변경하지 않고 같은 스크롤의 대상 지점 선택 상태를 유지한다.
- `GAME-173`: 정상 완료 후에는 스크롤 선택 가능 상태로 돌아가고, 실패 후에는 같은 스크롤의 대상 지점 선택 상태로 돌아간다.

`GAME-179`~`GAME-180`

- 몬스터 HP를 0으로 만든 마지막 실제 피해 원천 하나를 처치자로 기록한다.
- 여러 피해 원천이 관여해도 기본 처치 보상은 한 번만 지급한다.
- 현재 별도의 처치 시 발동 유닛 능력은 두지 않는다.

`GAME-185`

- 최대 강화·S등급 이후에도 중복 유닛·원소를 그대로 획득하고 보유한다.
- 자동 골드 변환과 다른 결과 재추첨은 하지 않는다.
- 추가 강화·승급 요청은 중복 재료와 골드 소비 없이 거부한다.

`GAME-184`

- 대상·단계·선행 조건·중복 재료·골드를 모두 먼저 검증한다.
- 성공할 때만 자원 차감과 강화 반영을 하나의 처리로 완료한다.
- 실패하면 자원과 강화 상태를 변경하지 않는다.

`GAME-186`

- 현지 시각 00시를 일일 접속 보상 날짜 경계로 사용한다.
- 로비 진입 시 오늘 미수령이면 보상 이벤트를 표시하고 골드 500을 자동 지급한다.
- 마지막 수령 현지 날짜를 저장해 같은 날짜의 중복 지급을 막는다.
- 누락일 보상과 연속 출석 보너스는 두지 않는다.

`GAME-187`, `SYS-054`

- 일일·주간 상품별 구매 완료 상태를 불리언으로 영구 저장한다.
- 구매 완료 상품은 같은 위치에 `이미 구매함`으로 표시하고 재구매를 막는다.
- JavaScript `Date`의 현지 시각을 사용해 일일은 매일 00시, 주간은 월요일 00시에 해당 값을 `false`로 초기화한다.
- 별도의 시스템 시계 조작 방지는 두지 않는다.

`GAME-188`~`GAME-189`

- 컬렉션은 신규 프로필부터 잠금 없이 바로 이용한다.
- 해금 전 기록과 소급 등록 절차를 두지 않는다.
- 같은 조건의 반복 달성은 등록이나 영구 효과를 중복시키지 않는다.

`GAME-206`~`GAME-207`

- 승리·일반 패배는 전투 종료 후 보상·컬렉션·통계를 계산해 한 번만 영구 저장한다.
- 저장 완료 후 저장된 정산 결과로 결과 화면을 표시한다.
- 중도 포기는 영구 보상 없이 런을 폐기한 뒤 결과 화면을 표시한다.

`PRD-004`

- 자동 전투를 관찰하면서 유닛 운영과 스크롤 사용으로 전략적으로 개입하는 경험을 핵심 플레이 가치로 둔다.
- 유닛 성장·원소 조합과 스크롤 위기 대응은 중심 경험을 지원한다.

`PRD-006`

- 기획상 주요 목표 사용자는 15세 이상 전략 게임 이용자다.
- 디펜스·로그라이트 경험과 25~30분 세션의 빌드 구성·반복 최적화를 선호하는 사용자를 중심으로 한다.
- 법적 연령등급은 별도 항목에서 결정한다.

`PRD-007`

- 공식 경쟁·비교작을 선정하지 않는다.
- 다른 게임을 기준으로 제품 방향이나 차별점을 정의하지 않는다.
- 사용자 원본 설정과 확정·승인된 자체 요구사항만 제품 방향의 근거로 사용한다.

`PRD-008`

- 본편은 Steam 일회성 유료 구매 제품으로 판매한다.
- 한 번 구매하면 최초 출시 범위의 전체 콘텐츠를 이용할 수 있다.
- 인앱 결제와 출시 시점 유료 DLC는 범위에서 제외한다.
- 가격·할인·판매 목표는 `PRD-064`~`PRD-066`으로 분리했다.

`PRD-013`~`PRD-014`

- 확정된 최초 출시 콘텐츠를 완성한 뒤 Steam 유료 완성판으로 정식 출시한다.
- 앞서 해보기와 최초 출시용 별도 무료 데모는 제공하지 않는다.
- 향후 데모를 추가하려면 별도 요구사항과 사용자 승인이 필요하다.

`PRD-018`, `PRD-019`, `PRD-035`, `PRD-036`

- 최초 출시는 일반 PC의 키보드·마우스 환경만 지원한다.
- Steam Deck과 일반 게임패드 조작은 최초 출시 범위에서 제외한다.
- Steam Deck Verified를 최초 출시 목표로 삼지 않는다.

`PRD-020`

- 최초 출시는 Windows 10·11 x64만 지원한다.
- macOS와 Linux는 최초 지원 운영체제에서 제외한다.
- 최소·권장 사양과 디스플레이 범위는 `PRD-067`~`PRD-068`으로 분리했다.

`SYS-008`

- Windows 10·11 x64 빌드만 지원한다.
- Windows ARM64, macOS와 Linux 빌드는 최초 출시에서 제외한다.

`SYS-007`

- Electron을 데스크톱 런타임으로 사용한다.
- Electron Forge로 Windows x64 배포물만 패키징한다.
- Phaser·TypeScript 게임은 Electron 렌더러에서 실행한다.

Windows 전용 출시 최종 결정

- Apple 개발자 계정·서명·공증 및 추가 검증 비용을 최초 출시에 부담하지 않는다.
- macOS 지원은 최초 출시 범위에서 제외한다.
- 향후 수익성과 필요성을 확인한 뒤 별도 승인으로 추가할 수 있다.

`SYS-072`~`SYS-073`

- Electron 렌더러에서 `contextIsolation`과 `sandbox`를 활성화하고 Node.js 직접 접근을 차단한다.
- 원격 코드를 로드하지 않고 패키징된 로컬 게임 자산만 실행한다.
- 저장·Steam 기능은 preload의 최소 API와 검증된 IPC로만 제공한다.

`SYS-119`

- 최초 Windows Steam 빌드는 코드 서명 인증서 없이 미서명으로 배포한다.
- 비공개 Steam 브랜치의 실제 설치본에서 보안 경고와 실행 차단 여부를 출시 전에 검사한다.
- 서명이 필요해지면 별도 요구사항과 사용자 승인으로 다시 결정한다.

`PRD-021`

- 최초 출시는 한국어만 지원한다.
- 다른 언어는 최초 출시 범위와 지원 표시에 포함하지 않는다.
- 출시 후 다른 언어를 추가할 가능성은 높지만 대상·시점·범위는 별도 승인한다.

`SYS-088`

- 모든 사용자 표시 문자열을 코드에서 분리하고 안정적인 문자열 ID로 참조한다.
- 최초 출시에는 한국어 리소스 파일만 제공한다.
- 추후 언어는 기존 ID에 대응하는 언어별 리소스 파일로 추가한다.

`SYS-089`

- 상업 이용·재배포 가능한 한국어 폰트를 게임 자산에 포함해 기본으로 사용한다.
- 누락 문자는 Windows 시스템의 한국어 지원 폰트로 fallback한다.
- 실제 폰트 제품명과 시각 스타일은 디자인 단계에서 별도 승인한다.

`SYS-090`, `UX-111`

- 일반 UI는 가변 크기·줄바꿈·스크롤을 기본으로 한다.
- 고정 HUD에서만 승인된 최소 글자 크기까지 제한적으로 축소한다.
- 말줄임표는 전체 문구 확인 경로가 있을 때만 사용한다.
- 숫자·날짜·시간 형식은 `SYS-120`으로 분리했다.

`SYS-120`

- 숫자는 천 단위 쉼표, 백분율은 `%`, 재화는 수치 뒤 재화명을 표시한다.
- 날짜는 `YYYY-MM-DD`, 시각과 경과 시간은 24시간제 `HH:MM:SS`를 사용한다.
- 추후 언어가 추가돼도 값 형식은 유지하고 문자열만 언어 리소스로 교체한다.

`PRD-023`~`PRD-027`

- 자동 플레이 분석·밸런스 로그 기능을 만들지 않는다.
- 플레이테스트 결과는 테스터가 직접 확인하고 별도로 기록한다.
- 플레이 분석 데이터를 로컬에 저장하거나 외부로 전송하지 않는다.
- 크래시 진단 로그는 별도 결정으로 남긴다.

`PRD-032`, `SYS-100`

- Steam 클라이언트와 인터넷 연결 없이 전체 싱글 플레이와 로컬 저장을 사용할 수 있다.
- Steam API 초기화 실패로 게임 실행을 막지 않는다.
- 향후 Steam 기능이 추가돼도 해당 기능만 비활성화한다.

`PRD-034`, `SYS-080`

- 최초 출시에서는 Steam 도전 과제와 Steam 통계를 지원하지 않는다.
- 관련 목록·기록·동기화와 Steamworks 연동을 구현하지 않는다.
- `SYS-080`의 남은 기술 결정 범위는 `PRD-033`의 Steam Cloud 채택 여부에 따른다.

`PRD-033`, `SYS-080`, `SYS-101`

- 최초 출시에서는 Steam Cloud를 지원하지 않고 진행·설정 데이터를 로컬에만 저장한다.
- Steam Cloud·Input·도전 과제·통계를 위한 Steamworks SDK·브리지·IPC를 구현하지 않는다.
- 클라우드 세이브 충돌·병합·동기화 처리를 구현하지 않는다.
- 이후 Steam 관련 선택은 최소 출시 범위와 비용을 우선한 추천안을 적용하되, 가격·일정 등 사업 판단은 사용자 결정을 받는다.

`PRD-028`, `PRD-066`

- 근거 없는 목표 판매량·매출·리뷰 수·환불률·플레이 유지율을 출시 전에 설정하지 않는다.
- 출시 후 실제 결과만 기록하고 목표 달성 여부로 판정하지 않는다.
- 향후 목표값이 필요하면 당시의 실제 자료를 근거로 별도 결정한다.

`PRD-064`

- 구체적인 출시 가격은 최종 콘텐츠 분량과 완성도가 확정된 출시 준비 단계에서 정한다.
- 기본 가격과 지역별 가격표를 함께 작성해 사용자 승인을 받은 뒤 Steamworks에 설정한다.
- 개발 중에는 근거 없는 임시 가격이나 가격대를 제품 요구사항으로 사용하지 않는다.

`PRD-065`

- 출시 할인은 적용하지 않는다.
- 출시 후 할인 시기와 할인율은 실제 판매 결과를 확인한 뒤 필요할 때 별도 결정한다.
- 별도 승인 전에는 Steamworks 할인 일정을 등록하지 않는다.

`PRD-067`

- 최소·권장 PC 사양은 최적화된 출시 후보 빌드를 여러 실제 Windows PC에서 시험한 뒤 정한다.
- 시험 전에는 개발 PC 사양이나 근거 없는 추정치를 제품 사양으로 사용하지 않는다.
- 측정 결과로 작성한 사양표는 사용자 승인 후 Steam 스토어에 게시한다.

`PRD-068`, `SYS-033`, `SYS-034`

- 1920×1080·16:9를 기준으로 제작한다.
- 창 모드와 전체 화면을 지원한다.
- 다른 기준 해상도·화면비와 울트라와이드용 별도 레이아웃은 최초 출시에서 제외한다.

`SYS-102`

- 16:9 범위에서는 창 크기와 모니터 배율에 맞춰 1920×1080 논리 화면을 비례 확대·축소한다.
- UI 배치는 바꾸지 않으며 고DPI·모니터 이동·최소화·복원·전체 화면 전환 후에도 입력 좌표를 일치시킨다.
- VSync·프레임 제한 결정은 `SYS-121`로 분리한다.

`SYS-013`, `SYS-121`, `UX-158`

- VSync를 기본 적용하고 30·60·120FPS 제한을 설정에서 선택하며 기본값은 60FPS로 한다.
- 선택값은 즉시 적용하고 로컬 설정에 저장한다.
- 전투 규칙과 시간 기반 효과는 렌더링 프레임 수가 아닌 경과 시간으로 계산한다.

`SYS-015`, `SYS-122`

- 게임 창이 포커스를 잃어도 자동 일시정지하지 않고 현재 배속으로 계속 진행한다.
- 사용자가 직접 일시정지한 상태는 포커스 상실·복귀로 바꾸지 않는다.
- 백그라운드에서도 경과 시간 규칙을 유지하고 복귀 순간 누락 시간을 중복 적용하지 않는다.

`SYS-103`

- 게임 창이 포커스를 잃어도 배경음과 효과음을 기존 음량으로 계속 재생한다.
- 포커스 복귀 시 오디오를 재시작하거나 중복 재생하지 않는다.
- 출력 장치 변경·분리 처리는 `SYS-123`으로 분리한다.

`SYS-123`, `UX-159`

- 설정에서 현재 사용 가능한 오디오 출력 장치를 사용자가 직접 선택한다.
- 선택은 배경음과 효과음에 함께 즉시 적용하고 로컬 설정에 저장한다.
- 사용자가 선택한 장치를 분리·제거하면 자동 전환·안내·일시정지를 하지 않고 소리만 나오지 않는다.

`SYS-031`, `SYS-032`

- 앞서 확정한 16:9 가변 확대·축소에 따라 논리 좌표계와 실제 창 크기를 분리한다.
- 1920×1080 논리 화면 전체와 UI 배치를 유지하고 포인터 입력을 논리 좌표로 변환한다.

`SYS-035`, `SYS-036`, `UX-078`

- 전체 음량과 배경음·효과음 개별 음량을 모두 제공한다.
- 전체 음소거는 기존 음량 값을 바꾸지 않고 출력만 끄며 해제하면 이전 값으로 복원한다.
- Scene·포커스 전환 후에도 배경음이 중복 재생되지 않게 한다.
- 최초 기본 음량값은 실제 음악·효과음을 넣고 상대 음량을 시험한 뒤 사용자 승인으로 정한다.
- 음원 통합 전에는 근거 없는 기본 음량 수치를 확정하지 않는다.

`SYS-037`, `UX-077`

- 일반 설정은 변경 즉시 적용하고 로컬에 자동 저장한다.
- 별도의 `적용` 버튼이나 재실행 요구를 두지 않는다.
- 저장 데이터 초기화처럼 확인이 필요한 작업은 일반 설정과 구분한다.

`SYS-038`

- 유효하지 않은 설정이 있으면 해당 설정 구역 전체만 기본값으로 복구한다.
- 다른 설정 구역과 게임 진행 저장 데이터는 유지한다.
- 복구값은 즉시 적용하고 정상 형식으로 다시 저장한다.

`SYS-039`, `UX-081`

- 설정 초기화는 모든 일반 설정을 되돌리는 전체 초기화 하나만 제공한다.
- 설정 구역별 초기화는 제공하지 않는다.
- 전체 설정 초기화는 게임 진행 저장 데이터를 변경하지 않는다.

`SYS-040`, `UX-082`

- 게임 진행 데이터 초기화를 전체 설정 초기화와 분리해 제공한다.
- 확인창에서 삭제 범위·설정 유지·복구 불가능을 안내하고 취소를 기본 안전 동작으로 둔다.
- 확정하면 영구 진행만 새 프로필 상태로 초기화하고 설정은 유지한 채 메인 화면으로 돌아간다.

`SYS-043`, `SYS-050`

- 정적 콘텐츠·일반 설정·영구 진행·현재 한 판 상태를 각각 분리한다.
- 한 데이터의 저장·초기화·복구가 다른 데이터를 변경하지 않게 한다.
- 정적 콘텐츠 JSON은 읽기 전용 배포 자산으로 관리한다.

`SYS-005`, `SYS-044`

- 모든 데이터는 REST API 응답처럼 명시적 필드와 관계를 가진 JSON 구조로 관리한다.
- 실제 백엔드·DB·네트워크 요청은 사용하지 않는다.
- 각 엔터티는 DB 기본키에 해당하는 고유 `id`를 가지며 관계는 해당 `id`를 참조한다.
- 표시명과 배열 순서는 식별자로 사용하지 않는다.

`SYS-045`

- 별도 스키마 버전 없이 게임 빌드·콘텐츠·설정·영구 진행에 공통 `version` 문자열 하나를 사용한다.
- 형식은 `1.0V`, `1.01V`, `2.0V`이며 소규모 패치는 소수부, 대규모 패치는 주 버전을 변경한다.
- 버전은 숫자가 아닌 문자열로 저장하고 비교한다.

`SYS-124`

- 구버전 JSON 구조가 현재 구조와 같으면 데이터는 유지하고 공통 버전만 갱신한다.
- 구조가 다르면 해당 이전 버전의 변환 규칙으로 현재 JSON 구조에 맞춘다.
- 변환 결과를 검증한 뒤에만 공통 버전을 현재 버전으로 갱신한다.
- 변환·검증 실패 시 기존 JSON을 덮어쓰거나 초기화하지 않고 그대로 보존하며 오류를 안내한다.

`SYS-125`

- 재화·뽑기·강화·보상·상점 구매·장착·정산 등 영구 데이터 변경이 확정될 때마다 즉시 저장한다.
- 저장 완료 전에는 작업을 최종 완료로 표시하지 않는다.
- 현재 한 판의 임시 전투 상태는 자동 저장하지 않는다.

`SYS-047`, `SYS-052`

- 영구 진행 JSON의 직전 정상 저장본 1개만 백업한다.
- 새 저장 전 현재 정상본을 백업하고 저장 실패 시 기존 정상본을 손상시키지 않는다.
- 현재본 손상 시 백업을 검증해 자동 복구하고 사용자에게 알린다.
- 현재본과 백업본이 모두 손상되면 둘 다 보존하고 오류만 표시한 뒤 종료한다.
- 자동 초기화와 게임 내 재시도·복구 선택지는 제공하지 않는다.

`SYS-046`

- 필드 자료형·범위·PK 중복·FK 존재 여부는 런타임에서 검사하지 않는다.
- 데이터 계약은 TypeScript 타입으로 개발 단계에서 관리하고 PK는 사용자가 확인한다.
- 실행 중에는 JSON 문법 오류처럼 데이터를 읽을 수 없는 경우만 실패로 처리한다.

`SYS-081`, `SYS-082`

- 저장 공간 부족이나 localStorage 접근·쓰기 실패 시 영구 변경을 완료하지 않는다.
- 변경 전 메모리·화면 상태와 기존 저장본을 유지하고 오류를 표시한다.
- 실패한 변경을 나중 저장하기 위해 메모리에 유지하지 않는다.

`SYS-126`

- 필수 콘텐츠 JSON이 없거나 JSON 문법 오류로 읽을 수 없으면 부팅을 중단한다.
- 임시 기본 데이터나 일부 콘텐츠 제외 실행은 제공하지 않는다.
- 오류를 표시한 뒤 게임을 종료한다.

`SYS-083`, `SYS-084`

- 이전 게임 빌드와 저장 JSON 하향 변환은 지원하지 않는다.
- 실행 빌드가 처리할 수 없는 더 새로운 저장 버전은 보존하고 오류 표시 후 종료한다.
- 버전 변환 실패 시 원본과 백업을 보존하고 자동 초기화·재시도·부분 저장 없이 종료한다.

`SYS-085`

- 감지해 표시하는 모든 오류는 오류 내용을 표시한 뒤 게임을 종료한다.
- 재시도·무시·계속 진행 조작은 제공하지 않는다.
- 저장 실패 시에도 변경을 취소하고 기존 저장을 보존한 뒤 종료한다.

`SYS-086`, `SYS-087`

- 마지막 크래시 진단 로그 1개만 로컬에 저장하고 새 로그로 덮어쓴다.
- 외부 전송과 사용자 내보내기 기능은 제공하지 않는다.
- 개인정보·영구 진행 JSON·플레이 행동 내역은 로그에 포함하지 않는다.
- 크래시 로그 필드는 발생 시각·게임 버전·오류 이름·오류 메시지·스택 정보로 제한한다.
- 별도 플레이테스트 진단 로그는 만들지 않는다.

`SYS-099`

- 한 번 출시된 콘텐츠 PK는 변경·재사용하지 않는다.
- 제거 대상도 같은 PK의 `inactive` JSON 레코드로 남겨 기존 저장 참조를 유지한다.
- PK 삭제·교체·보상을 위한 저장 변환표는 만들지 않는다.
- `inactive` 콘텐츠는 신규 획득·상점·보상에서 제외한다.
- 비활성화 전 보유자는 기존과 동일하게 조회·장착·강화·사용할 수 있다.

`SYS-093`

- 별도 세이브 스키마 버전 범위를 관리하지 않는다.
- 현재 공통 버전과 명시적으로 등록된 이전 버전의 상향 변환만 지원한다.
- 더 새로운 저장과 하향 변환은 지원하지 않는다.

`SYS-092`

- 공통 버전별 한국어 릴리스 노트를 작성한다.
- 버전·배포일과 신규·변경·버그 수정·저장 데이터 변환 여부를 구분한다.
- 저장 구조가 바뀌지 않아도 변환 없음 여부를 표시한다.

`SYS-091`, `UX-011`

- 메인 화면 진입 전 로딩 화면에 게임 로고·로딩 표시·공통 버전을 표시한다.
- 설정 화면과 크래시 로그도 같은 패키지 버전 메타데이터를 사용한다.
- 빌드 ID와 가짜 진행률은 표시하지 않으며 초기화 완료 즉시 메인으로 이동한다.
- 오류 화면은 로딩·정상 화면과 구분하고 재시도를 제공하지 않는다.

`SYS-098`

- 게임 버전 변경을 위한 별도의 localStorage 키 namespace·실행 origin·업데이트 저장 정책을 추가하지 않는다.
- 기존 영구 데이터의 버전 유지·변환·실패 처리는 `SYS-124`만 따른다.
- 설치·제거·재설치 등 배포 수명주기의 데이터 처리는 `SYS-105`에서 별도로 정한다.

`SYS-105`

- 설정·세이브와 마지막 크래시 로그는 게임 설치 폴더와 분리된 Electron 사용자 데이터 영역에 저장한다.
- Steam 설치·업데이트·파일 무결성 검증·롤백·제거·재설치에서는 사용자 데이터를 삭제하거나 초기화하지 않는다.
- 구버전 롤백이 더 새로운 저장 버전을 지원하지 않으면 원본을 보존하고 오류 표시 후 종료한다.
- 영구 진행과 설정은 게임 안의 승인된 초기화 기능으로만 삭제한다.
- 사용자가 운영체제의 사용자 데이터 폴더를 직접 삭제하거나 외부 정리 도구가 삭제한 데이터는 복구하지 않는다.

`PRD-037`

- 정기 업데이트 주기를 두지 않는다.
- 수정·콘텐츠가 준비되고 승인된 검증을 통과했을 때만 업데이트한다.
- 버전·릴리스 노트·세이브 상향 변환·롤백·로컬 데이터 유지는 기존 확정 시스템 요구사항을 따른다.

`PRD-039`, `UX-160`

- 밝고 선명한 귀여운 판타지와 비사실적인 무기·마법·원소 이펙트를 전투 표현 기준으로 사용한다.
- 혈흔·현실적인 상처·신체 훼손·절단·시체와 사실적인 공포 표현은 사용하지 않는다.
- 해골·악마·뱀파이어와 검붉은 마법은 허용하되 작은 신체 비율, 단순화된 형태와 굵은 외곽선을 유지한다.
- 예시 이미지에 없는 뽑기 연출은 추론하지 않고 `PRD-069`로 분리한다.

`PRD-069`, `UX-161`

- 유닛·원소 뽑기는 마법진이나 빛에서 결과가 등장한 뒤 등급 색상과 획득 대상을 공개한다.
- 룰렛·슬롯·칩·베팅 등 카지노나 도박을 직접 연상시키는 표현은 사용하지 않는다.
- 10회·100회 결과는 묶어서 확인하며 각 결과마다 1회 전체 연출을 강제로 반복하지 않는다.

`PRD-040`

- 개발 중 생성형 AI로 만든 결과물을 사람이 검수·수정한 뒤 출시용 사전 제작 자산으로 사용할 수 있다.
- 사용 도구·대상 자산·수정·검수 여부를 기록하고 Steam Content Survey에 사실대로 신고한다.
- 게임 실행 중에는 생성형 AI 모델이나 외부 AI API로 새 콘텐츠를 생성하지 않는다.

`PRD-043`

- 별도 사용자 결정 전에는 개인정보·플레이 분석·충돌·성능 데이터를 수집하거나 외부로 전송하지 않는다.
- 계정, 원격 분석과 외부 진단 서비스를 도입하지 않는다.
- 게임 진행·설정과 마지막 크래시 로그 1개는 로컬에만 보관한다.

`PRD-038`

- 출시 후보 빌드의 실제 콘텐츠를 기준으로 Steam Content Survey를 사실대로 작성한다.
- 비사실적 판타지 전투 표현과 사전 제작 생성형 AI 자산 사용을 반영한다.
- 출시 자산이나 콘텐츠 표현이 바뀌면 제출 전 설문도 갱신한다.

`PRD-041`

- 크레딧 표시 의무가 있는 외부 자산만 출처·제작자·라이선스·표시 문구를 장부에 기록한다.
- 표시 의무가 없는 자산은 별도 장부에 기록하지 않는다.
- 출시 빌드에는 표시 의무와 관계없이 상업 이용이 허용된 자산만 포함한다.

`PRD-042`

- Steam 스토어에는 출시 후보 빌드에서 실제로 확인할 수 있는 기능·콘텐츠·화면만 사용한다.
- 개발용 목업·예시 이미지·미구현 기능을 실제 게임 내용처럼 표시하지 않는다.
- 빌드 변경으로 차이가 생기면 출시 전에 스토어 자료를 갱신한다.

`PRD-030`, `PRD-031`, `SYS-079`

- Windows 10·11 x64의 비공개 Steam 브랜치 실제 설치본으로 출시 검증을 수행한다.
- 다운로드·설치·첫 실행·핵심 플레이·저장·재실행·업데이트·파일 무결성 검사를 포함한다.
- 스토어에 표시한 모든 지원 기능을 제출 후보 빌드에서 확인하며 로컬 빌드 시험만으로 대체하지 않는다.

`PRD-017`

- 플레이어·개발자·디자이너·QA·Steam 심사를 주요 이해관계자로 각각 구분한다.
- 사용성·개발 가능성·디자인 일관성·검증 가능성·출시 조건을 해당 관점에서 확인한다.

`UX-012`

- 별도의 시작·타이틀·입력 대기 화면을 두지 않는다.
- 로딩과 초기화가 끝나면 추가 입력 없이 바로 메인 화면으로 이동한다.
- 게임 시작·설정·종료 등 메뉴 기능은 메인 화면에서만 제공한다.

## 최근 인게임 UX·컬렉션 결정

`UX-134`, `UX-138`, `UX-166`~`UX-169`

- 고정 카메라로 맵 안의 8×8 전투 영역 전체와 주변 환경을 함께 표시한다.

- 구체적인 재생 시간과 프레임 수는 별도 승인 전까지 확정하지 않는다.

`UX-141`

- 디자이너는 확정·승인된 화면 구조, 정보 위계, 시각 방향과 상호작용을 유지하는 범위에서 색상 세부값, 간격, 선 굵기와 애니메이션 프레임 수를 결정할 수 있다.
- 화면 추가·삭제, 정보 우선순위 변경, 주요 영역 재배치, 조작 방식 변경과 기존 요구사항과 다른 시각 방향은 적용 전에 사용자 승인을 받는다.

`UX-093`

- UX 검증의 대표 플레이어는 PC 키보드·마우스 사용에는 익숙하지만 DefenseLike의 규칙과 조작은 처음인 플레이어다.
- 최초 이용 흐름, 정보 이해와 조작 학습 여부는 이 대표 플레이어와 개인 PC·1인 플레이 환경을 기준으로 검증한다.

`UX-094`

- 최초 이용 시험에서는 게임 내 튜토리얼과 가이드 도움말을 사용할 수 있다.
- 진행자의 설명이나 외부 자료 없이 게임 시작, 유닛 뽑기·배치·승급·판매, 스크롤 구매·대상 선택·사용과 결과 확인을 완료해야 독립 성공으로 판정한다.
- 진행자가 수행 방법이나 정답을 설명한 과업은 완료하더라도 독립 성공과 구분한다.

`UX-095`

- 플레이 테스트는 참여자별 수동 기록표로 남기며 실명 대신 익명 참여자 번호를 사용한다.
- 빌드·해상도·튜토리얼 사용 여부와 과업별 판정·시간·오류·도움 요청·관찰 의견·종료 후 의견을 기록한다.
- 과업 판정은 독립 성공, 도움 후 성공, 실패로 구분한다.
- 게임 내부 자동 수집은 추가하지 않고, 화면 녹화는 참여자 동의를 받은 경우에만 보조 자료로 사용한다.

`UX-096`

- 핵심 과업이 독립 성공하지 못하면 수동 기록표를 근거로 실패 원인을 식별한다.
- 요구사항이나 디자인 변경은 사용자 승인 후 수정한다.
- 수정된 빌드는 기존 참여자가 아닌 새로운 대표 플레이어에게 같은 조건과 과업으로 재시험한다.
- 실패 원인, 승인된 변경, 빌드 버전과 재시험 결과를 연결해 기록한다.

`UX-097`

- 세계의 시대·기술 수준은 검·활·마법 중심의 중세 판타지다.
- 주요 전투 장소는 중세 왕국의 변방 성채와 마을 주변이다.
- 분위기는 밝고 선명한 귀여운 판타지를 따른다.
- 최초 출시에는 도입 서사, 대화, 컷신, 등장인물 관계와 세계관 설명을 포함하지 않고 게임 규칙·조작·상태를 전달하는 기능성 문구만 제작한다.

`UX-098`

- 픽셀 아트나 3D 모델 사전 렌더링이 아닌 굵은 외곽선의 일반 2D 일러스트형 스프라이트를 사용한다.
- 움직임은 2D 스프라이트 프레임 애니메이션으로 표현한다.
- 구체적인 프레임 수는 디자이너 위임 범위에서 정하고 대상별 제작 목록은 별도로 확정한다.

`UX-113`

- `기사.png`와 `마법사.png`를 기준으로 약 2.5~3등신의 큰 머리·작은 몸·짧은 팔다리를 사용한다.
- 단순한 얼굴과 둥근 형태, 굵고 어두운 외곽선, 선명한 색 대비를 유지한다.
- 투구·모자·무기·방패·지팡이처럼 직업을 식별하는 장비를 신체보다 크게 강조한다.
- 참고 이미지의 문구·서사는 사용하지 않으며 실제 전투 스프라이트 크기는 별도로 정한다.

`UX-119`

- 전투 유닛은 약 2.5~3등신 비율을 유지하고 소유 배치 칸 중심에 접지한다.
- 몸체의 핵심 실루엣은 자기 칸에 대응하는 영역에서 식별되게 한다.
- 모자·투구·무기·방패는 인접 유닛의 얼굴·몸체, 칸 경계와 조작 대상을 가리지 않는 범위에서만 조금 돌출할 수 있다.
- 실제 픽셀 높이는 1920×1080의 전체 6×6 배치 상태에서 가독성을 확인한 뒤 디자이너가 정한다.

`UX-090`

- 여러 속성이 함께 표시될 때 시각 우선순위는 직업 또는 몬스터 종족, 원소, 등급 순이다.
- 직업·종족은 실루엣·대표 장비·자세, 원소는 색·문양·아이콘과 공격·스킬 효과, 등급은 장비 재질·장식·문양과 추가 효과로 구분한다.
- 원소와 등급 표현은 직업·종족의 핵심 실루엣과 행동을 가리지 않고 색상에만 의존하지 않는다.

`UX-091`

- 동시 재생 믹싱 우선순위는 위험 경고·스크롤 성공/실패음, 주요 전투 효과음, UI 조작음, 배경음악 순이다.
- 낮은 순위의 소리는 높은 순위 사건의 식별을 가리지 않게 조정한다.
- 정확한 데시벨과 조정 방식은 실제 음원 통합 후 동시 재생 시험으로 정하며, 음소거 상태의 시각 정보는 유지한다.

`UX-162` 원소 표시 보완

- 일반 몬스터와 보스의 체력바 오른쪽에 실제 원소와 일치하는 원소 문양을 표시한다.
- 다섯 원소 문양은 색상을 제거해도 형태로 구분할 수 있어야 한다.
- 보스는 원소 문양과 기존 보스 아이콘을 함께 표시하며 세부 간격과 순서는 디자이너 위임 범위에서 정한다.

`UX-088`

- 다섯 원소는 몬스터 원소 문양과 같은 형태 체계를 사용하고 회색조에서도 구분한다.
- 별도의 유닛 머리 위 원소 UI와 발밑 원소 고리는 표시하지 않는다.

`UX-106`, `UX-188`

- 서로 다른 최상위 화면으로 이동하면 이전 곡과 새 곡을 짧게 교차 전환하고 완료 후 새 곡 하나만 남긴다.
- 구체적인 교차 전환 시간은 실제 음원 시험 전까지 고정하지 않는다.
- 인게임은 일반층·보스층·구간·난이도와 관계없이 한 종류의 공통 배경음악을 사용하며 보스 전용 음악은 두지 않는다.
- 사건별 효과음 제작 목록과 재사용 범위는 확정된 `UX-188`을 따른다.

`UX-188`
