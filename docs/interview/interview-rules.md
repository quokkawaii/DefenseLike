# 기획 인터뷰 규칙

## 목적

정본의 `제안` 및 `미정` 요구사항을 사용자 인터뷰를 통해
`확정` 또는 필요한 상태로 변경한다.

## 진행 순서

인터뷰는 원칙적으로 다음 순서로 진행한다.

1. 콘텐츠·캐릭터 정의
2. 기본 행동
3. 등급별 변화
4. 공격·스킬 세부 규칙
5. 예외
6. 밸런스 수치

앞 단계의 결정이 필요한 항목을 뒤 단계에서 먼저 확정하지 않는다.

## 질문 준비

- 정본의 최신 상태를 기준으로 질문한다.
- 현재 결정과 관련된 요구사항을 검색한다.
- 필요한 경우 관련 ID와 연관 요구사항을 추가 검색한다.
- 이미 `확정`, `승인`된 내용은 다시 질문하지 않는다.
- 같은 의미의 요구사항이 이미 존재하는지 확인한다.
- 관련된 여러 요구사항을 하나의 응집된 결정으로 답할 수 있을 때는 하나의 질문으로 묶는다.
- 필요한 정보를 검색할 수 있다면 전체 요구사항 파일을 다시 읽지 않는다.

## 질문 규칙

- 한 번에 질문 하나만 한다.
- 선택지는 2~4개 제공한다.
- `직접 입력` 선택지는 표시하지 않는다.
- 각 선택지의 게임 규칙·제작 범위·사용성 차이를 짧게 설명한다.
- 기존 확정 사항과 구현 범위에 적합한 안이 있으면 `추천안`으로 표시할 수 있다.
- 추천에는 근거를 제시한다.
- 밸런스 수치를 임의로 생성하지 않는다.

## 답변 처리

인터뷰 질문에 대한 사용자의 답변은 그 항목에 한해 정본 반영 허락으로 간주한다(`AGENTS.md`의 "데이터 수정은 사용자 허락을 받는다"를 인터뷰 맥락에서 충족한 것으로 본다).

사용자의 답변을 받은 뒤:

1. 결정 내용을 관련 정본에 반영한다.
2. 직접적으로 영향을 받는 관련 요구사항을 확인한다.
3. 필요한 상태를 갱신한다.
4. `docs/interview/interview-state.md`의 현재 작업·다음 작업·집계를 갱신한다.
5. 결정 내용과 필요한 경계를 짧게 요약한다.
6. 다음 질문을 준비한다.

답변마다 하는 검사는 위 2번(직접 영향을 받는 관련 요구사항)으로 한정하며, 전체 요구사항 충돌 검사는 하지 않는다.
인터뷰 묶음이 끝나면 `docs/AGENTS.md`가 요구하는 4개 문서 전체 검증을 별도로 1회 수행한다.

## 상태

### 미정
사용자의 결정이 필요하다.

### 제안
제안된 요구사항이며 사용자의 승인·수정·보류가 필요하다.

### 확정
사용자가 결정했다.

### 승인
항목별 리뷰까지 통과했다.

`확정`, `승인`은 변경 사유가 발생하지 않는 한 다시 인터뷰하지 않는다.

## 다음 질문 선정

현재 인터뷰 묶음이 끝나면:

1. 정본에서 남아 있는 `제안`, `미정`을 탐색한다.
2. 인터뷰 진행 순서에 따라 다음 대상을 선정한다.
3. 관련된 요구사항을 검색한다.
4. 중복 및 선행 결정 여부를 확인한다.
5. 다음 질문을 작성한다.

## 진행률

실제 인터뷰 시작 시 `제안 + 미정`을 기준으로 질문 계획을 만든다.

원본 요구사항 수와 실제 질문 수는 동일하게 취급하지 않는다.

여러 요구사항이 하나의 결정으로 묶이면 하나의 질문으로 계산한다.

후속 결정이 추가되면 예상 질문 수를 갱신한다.

## 질문 형식

    - 남은 원본 요구사항: N개
        - 제안: N개
        - 미정: N개
    - 예상 남은 질문: N개
    - 전체 요구사항: N개
    - 확정·승인 완료: N개

관련 요구사항: GAME-000 등

질문

1. 선택지 — 핵심 영향
2. 선택지 — 핵심 영향
3. 선택지 — 핵심 영향

## 테스트 인터뷰

- 테스트 질문 수는 실제 인터뷰와 별도로 계산한다.
- 테스트 답변은 사용자가 반영을 요청하지 않는 한 정본에 반영하지 않는다.
