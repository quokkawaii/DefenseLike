DefenseLike · Workflow Policy

GitHub PR 훅 운영 계획

PR은 자동으로 생성하지 않는다. 사용자가 요청하면 최신화와 검증을 진행하고, 한국어 미리보기를 보고한 뒤 최종 승인을 받아 생성한다.

수동 시작사용자가 PR을 요청한 경우에만 준비한다.
먼저 최신화원격 main을 반영하고 충돌 여부를 확인한다.
한국어 보고제목·본문·변경 파일을 생성 전에 보여준다.
승인 후 생성명시적인 허락 전에는 push와 PR 생성을 하지 않는다.
PR 생성 절차 보고 형식 머지 이후 예외 처리 구현 원칙
1

사용자 요청형 PR 생성 절차

01

사용자가 PR을 요청한다

“PR 준비해”, “PR 올려줘”처럼 명시적으로 요청한 경우에만 워크플로를 시작한다.

사용자 시작
02

현재 상태를 점검한다

현재 브랜치, 변경 파일, 미커밋 작업, 대상 브랜치와 원격 저장소를 확인한다.

로컬 검사
03

PR 대상 변경을 커밋한다

사용자가 작업한 다른 변경이 섞이지 않도록 이번 작업에 해당하는 파일만 포함한다.

범위 제한
04

GitHub 최신 상태를 반영한다

origin의 최신 정보를 가져오고 현재 작업 브랜치를 최신 origin/main 위로 재배치한다.

fetch + rebase
05

충돌 여부를 확인한다

충돌이 발생하면 자동 해결하지 않고 파일 목록과 현재 상태를 사용자에게 보고한 뒤 중단한다.

충돌 시 중단
06

변경사항을 검증한다

가능한 테스트와 문법 검사를 실행하고, 실제 커밋과 변경 파일 목록을 다시 확인한다.

검증
07

한국어 PR 초안을 보고한다

제목, 본문, 브랜치, 커밋, 변경 파일과 검증 결과를 사용자가 읽기 쉽게 정리한다.

미리보기
08

사용자의 최종 승인을 기다린다

승인하면 push와 PR 생성을 진행한다. 수정 요청이면 초안을 바꿔 다시 보고하고, 취소하면 생성하지 않는다.

승인 필수
09

PR을 생성하고 결과를 보고한다

승인된 내용 그대로 GitHub에 올린 뒤 PR 번호와 URL을 전달한다. 자동 머지는 하지 않는다.

완료
2

PR 생성 전 보고 형식

[PR 생성 예정]

대상 브랜치:
main

변경 내용:

- 한국어 PR 제목과 본문 생성
- 사용자 최종 승인 이후에만 push 및 PR 생성

검증 결과:
- 훅 설정 형식 검사 완료
- 셸 스크립트 문법 검사 완료
- 원격 main과 충돌 없음

이 내용으로 PR을 생성할까요?
3

머지 이후 최신화와 브랜치 생성

01

사용자가 머지 완료를 알린다

“머지했어”라는 알림이 새 작업 준비의 시작 신호다.

사용자 시작
02

미커밋 변경을 확인한다

작업 트리가 깨끗하지 않으면 main 전환 전에 변경 파일을 보고하고 진행을 멈춘다.

안전 점검
03

main을 최신화한다

main으로 전환한 뒤 origin/main을 fast-forward 방식으로 가져와 머지 결과를 반영한다.

pull --ff-only
04

이전 브랜치 삭제 여부를 확인한다

GitHub 원격 브랜치와 로컬 브랜치를 따로 확인한다. 남아 있어도 임의로 삭제하지 않고 상태만 보고한다.

삭제 상태 보고
05

새 브랜치 주제를 확정한다

사용자가 이미 주제를 말했다면 그 의미로 브랜치명을 만들고, 정하지 않았다면 먼저 질문한다.

주제 확인
06

최신 main에서 새 브랜치를 만든다

브랜치명과 기준 커밋, 작업 트리 상태를 최종 보고하고 다음 작업을 시작한다.

새 작업 준비
4

중단하거나 확인해야 하는 경우

즉시 중단

  • rebase 또는 최신화 과정에서 충돌 발생
  • main에 직접 PR 작업을 올리려는 상태
  • PR 대상이 아닌 사용자 변경이 섞인 상태
  • 원격 저장소나 대상 브랜치를 확인할 수 없는 상태

사용자에게 질문

  • PR 제목이나 포함 범위가 불명확함
  • 머지 후 새 브랜치 주제가 정해지지 않음
  • 이전 원격·로컬 브랜치 삭제가 필요함
  • 검증 실패를 수정할지 결정해야 함

승인 후 실행

  • 작업 브랜치 원격 push
  • 한국어 제목·본문으로 PR 생성
  • 기존 브랜치 삭제
  • 충돌 파일 수정 후 rebase 계속

자동으로 하지 않음

  • 작업 종료만으로 PR 생성
  • 충돌 내용의 임의 선택
  • PR 자동 머지
  • 사용자 변경 전체를 일괄 스테이징
5

Codex 훅 구현 원칙

UserPromptSubmit 훅

사용자 프롬프트를 기준으로 PR 요청 또는 머지 완료 상황을 감지하고, 해당 워크플로 규칙을 Codex의 추가 작업 지침으로 전달한다.

  • 일반 요청: 기존 AGENTS.md만 로드
  • PR 요청: PR 준비·최신화·보고 절차 적용
  • 머지 알림: main 최신화·브랜치 확인 절차 적용

Stop 훅

PR 생성 트리거로 사용하지 않는다. Stop은 턴 종료 시 실행될 수 있어, 사용자가 원할 때만 PR을 요청한다는 정책과 맞지 않는다.

  • 원격 변경 생성 금지
  • 승인 상태 추측 금지
  • 재귀적인 작업 지속 방지
